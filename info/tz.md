## 15. Критерии готовности MVP (приёмка)

`[УРОК]`-структура, адаптирована `[ПРЕДПОЛОЖЕНИЕ]`:
1. Пользователь может войти и выйти; сессия сохраняется после обновления.
2. Админ создаёт проекты и пользователей, меняет роли.
3. Руководитель создаёт и редактирует задачи, назначает исполнителя, срок и приоритет.
4. Задачи отображаются списком и на канбан-доске.
5. Карточки перемещаются между колонками; статус обновляется автоматически.
6. Работают комментарии (свои — редактирование/удаление, админ — любые).
7. Работают фильтры и поиск по задачам.
8. Просроченные задачи визуально выделяются.
9. Уведомления появляются внутри приложения.
10. Интерфейс корректно отображается на компьютере и смартфоне.
11. После обновления страницы данные не исчезают (хранятся в MySQL).
12. Пользователь не видит проекты, к которым у него нет доступа.
13. Присутствуют демо-данные.
14. Нет критических ошибок, блокирующих основные сценарии.

## 17. Демо-данные `[ПРЕДПОЛОЖЕНИЕ]`

- 8–9 пользователей (3 роли), 3 проекта с разными статусами.
- Не менее 20–25 задач с разными статусами и приоритетами, несколько просроченных.
- Комментарии и записи истории к задачам.
- Пример сценариев: руководитель → создание и назначение задачи; сотрудник → изменение статуса и комментарий (для теста прав).

## 18. Ожидаемый результат кейса

Готовое адаптивное веб-приложение на **PHP 8.0 + MySQL 8.0** с ролями и канбан-доской, демо-данными, прошедшее тестирование и итерации по циклу урока, с применённым брендингом, опубликованное на GitHub и (при доступном Railway/сервере) в сети с публичной ссылкой.
